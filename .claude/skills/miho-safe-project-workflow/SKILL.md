# miho-safe-project-workflow

このリポジトリ（三保〜清水港 津波避難×災害伝承 AR学習支援システム）で変更作業を行うときの
必須ワークフロー。`CLAUDE.md` / `CONTRIBUTING.md` の制約と併せて適用する（矛盾したらそちらが優先）。

大前提: このアプリは**平時の防災学習・避難訓練支援用の試作**であり、実災害時の避難誘導には使わない。
この前提を壊す変更・表現は、依頼されても一度立ち止まって確認する。

## フェーズ1: 調査（この段階では実装しない）

- **コードを1行も編集しない。** まず GitHub 上のリポジトリ
  （towa1824/miho-tsunami-densho-ar）とそのチェックアウトを調査する。
  必要に応じて Issues / PR / CI の履歴も確認する。
- 依頼に関係する `src/` / `data/` / `tools/` / 設定ファイルを読み、影響範囲を特定する。
- `CLAUDE.md` と `CONTRIBUTING.md` の制約に依頼内容が抵触しないか確認する。
- **外部仕様が不明なら推測で埋めない。** LocAR.js / three.js / OSRM / Overpass /
  Nominatim / Google Maps・Routes API などの外部仕様は、公式ドキュメント・
  ライブラリの実コードなど一次情報を実際に確認してから判断する。
  確認できなかった場合は不明点を具体的な質問として列挙し、そこで作業を止める。
  外部docsを見たふりで判断しない。

## フェーズ2: 範囲宣言 → 承認待ち（必ず一旦停止する）

調査結果として以下を報告し、**ユーザーの明示的なOKが出るまで実装に進まない**:

- 変更対象ファイル（それぞれ何をどう変えるか）
- 変更**しない**もの（特に下記「変更禁止範囲」との関係）
- 何が達成されれば成功か（成功条件）
- 検証方法（フェーズ4のどのコマンド・確認を行うか）
- 未確認の外部仕様・残っている不明点（あれば）

## フェーズ3: 最小実装

- 承認された範囲**だけ**を外科的に変更する。依頼外の整理・リファクタ・「ついで修正」はしない。
- **大きな変更は段階分割する**（1段階 = 1検証単位）。各段階で検証を通してから次の段階へ進む。
- 依存関係の追加・更新は「何を・なぜ」を1行で宣言して承認を得てから行う。
  依存関係の一括・大幅更新はしない。
- 座標・施設・伝承データはソースコードにハードコードせず `data/*.json` に置く。

## フェーズ4: 検証

- `npm run build` — 必須。本番ビルドが通ること（CIと同条件）。
- `npm run validate:data` — `data/*.json` を変更した場合は必須
  （id重複・出典・座標・location_kind の整合チェック）。
- UI・表示に関わる変更は `npm run dev:http`（simモード・デモGPS）で画面確認する。
- live ARモード（HTTPS＋カメラ＋方位センサー）はこの環境では検証できない。
  変更が live に影響しうる場合は**未検証項目として明示**し、実機確認が必要と報告する。

## フェーズ5: 報告

作業後に必ず以下を報告する:

- 変更ファイル一覧
- 各変更の理由（何のためにその変更をしたか）
- 実行した検証とその結果（コマンドと出力の要点）
- **未検証項目**（live AR・屋外GPS・Google APIキー必要機能など、確認できなかったこと）
- 残課題・フォローアップがあればその内容

## 変更禁止範囲（依頼に含まれていても、まず確認を取る）

- UIの注意文（「平時の防災学習用の試作」「実際の災害時は公式情報に従って避難」等）の削除・弱体化
- attribution表記の削除（`#arAttrib`・「© OpenStreetMap contributors」・`NOTICE.md`・注意事項タブ）
- live ARモードを壊す変更（既定は sim。live はユーザーが明示的に選んだ時のみ動く導線を維持）
- 既存の UI / AR表示 / 地図(Leaflet・Google切替) / ルーティング(OSRM→Google→直線フォールバック) /
  `data/*.json` のデータ構造を壊す変更
- 出典（`source_title` / `source_url`）のないレコードの追加、推測座標の記入、
  伝承・史料だけを根拠に「安全/危険」を断定する文言
- 技術スタックの置き換え（LocAR.js + three.js + Vite 固定。AR.js旧版・センサー再発明は禁止）
- Overpass / Nominatim / OSRM のキャッシュ・レート制御（1req/秒、localStorage 7日、
  `tools/geocode_cache.json`）の削除・迂回
- `.github/workflows/` の CI・Pagesデプロイ、および main 保護の前提を崩す変更

## Git / 提出

- `main` へ直接 push しない。変更はブランチで行い **PR で提案**する。**PR を自動でマージしない**
  （マージは owner が判断・実行する）。
- push・PR作成は、ユーザーの指示があった時のみ行う。
